Google Play phone screenshots are usually 1080x1920 or 1080x2400, the feature graphic is 1024x500 and the app icon is 512x512. Open Assets renders all of them, plus 7" and 10" tablet screenshots, from HTML templates.

A Google Play store listing needs three kinds of graphics: phone screenshots, a feature graphic and a high resolution app icon. Each is a collection in Open Assets.

## Google Play sizes

As of 2026-11-17, Google's rules are:

| Asset | Rule |
| --- | --- |
| Screenshots | JPEG or 24-bit PNG (no alpha), 320px to 3840px per side, long side at most twice the short side, up to 8 per device type |
| Promotion eligibility | At least 4 screenshots at 1080px or more (1080x1920 portrait) for apps |
| Tablets and Chromebooks | At least 4 screenshots, 1080px to 7680px, 16:9 or 9:16 |
| Feature graphic | 1024x500, JPEG or 24-bit PNG (no alpha) |
| App icon | 512x512, 32-bit PNG with alpha, up to 1024 KB |

## Tablet screenshots (7" and 10") [#tablets]

Add tablet sizes as `export` entries. The Tax Days example renders 7" and 10" tablet sizes (1200x1920 and 1600x2560) from its phone templates:

```json title="assets.json (from examples/tax-days)"
"export": [
  { "name": "phone", "size": { "width": 1080, "height": 2400 } },
  { "name": "tablet-7", "size": { "width": 1200, "height": 1920 } },
  { "name": "tablet-10", "size": { "width": 1600, "height": 2560 } }
]
```

From a `440x978` phone source the tablet renders scale to fill the width and crop the bottom, as below. That works for a framed phone layout; for a tablet first layout give tablets their own collection with a 10:16 source such as `400x640`.

## Phone screenshots

Android phones are taller than the 440x956 iPhone source. A 1080x2400 screenshot has a 9:20 ratio, so use a source of `440x978` (the Tax Days and Only Recipes examples do). You can usually reuse your iPhone templates' styles and just give the Android templates the taller canvas.

Rendering scales by the larger of the width and height ratios and captures from the top left, so if a source and export ratio differ, the extra is cropped from the right or bottom. That is why the Play Store collection should not share a source size with the iPhone collection.

## Google Play feature graphic size [#feature-graphic]

The feature graphic is 1024x500 and appears at the top of your listing and in promotions. Author it at full size. Keep text away from the edges and center the key message, since Play can crop or overlay it on some surfaces. The [feature graphic guide](/guides/google-play-feature-graphic) has a full walkthrough.

## Collection config

```json title="assets.json"
{
  "collections": [
    {
      "id": "play-screenshots",
      "label": "Play Store Screenshots",
      "sourceSize": { "width": 440, "height": 978 },
      "templates": [
        { "src": "assets/play/01-hero.html", "name": "01-hero", "label": "Hero" },
        { "src": "assets/play/02-features.html", "name": "02-features", "label": "Features" }
      ],
      "export": [
        { "name": "phone", "label": "Phone", "size": { "width": 1080, "height": 2400 } }
      ]
    },
    {
      "id": "feature-graphic",
      "label": "Feature Graphic",
      "sourceSize": { "width": 1024, "height": 500 },
      "templates": [
        { "src": "assets/play/feature-graphic.html", "name": "feature-graphic" }
      ],
      "export": [
        { "name": "feature-graphic", "size": { "width": 1024, "height": 500 }, "outFile": "exports/play/feature-graphic.jpg" }
      ]
    },
    {
      "id": "play-icon",
      "label": "Play Icon",
      "sourceSize": { "width": 1024, "height": 1024 },
      "templates": [
        { "src": "assets/icon/icon.html", "name": "icon" }
      ],
      "export": [
        { "name": "play-icon", "size": { "width": 512, "height": 512 } }
      ]
    }
  ]
}
```

What this produces:

- `exports/play-screenshots/phone/01-hero.png` and friends (one folder per size, because the collection has several templates).
- `exports/play/feature-graphic.jpg`. The feature graphic must not have transparency, and a `.jpg` `outFile` is rendered as JPEG, which has none.
- `exports/play-icon/play-icon.png`. A single-template collection writes flat files named after the size.

The icon collection reuses the same template as your iOS icon. One source of truth, every store.

You can also start the feature graphic with `npx open-assets add collection` and the "Feature Graphic / Google Play" preset.

## Localized Play listings

Play Console has per-language graphics too. Add `localizations` to the screenshot collection and each locale renders into its own folder: `exports/play-screenshots/de/phone/01-hero.png`. See [Localization](/localization).

## Steps

1. Capture your Android app (or reuse iPhone captures) into `public/`.
2. Add a `play-screenshots` collection with a `440x978` source and the phone and tablet sizes you need.
3. Add the feature graphic and icon collections from the config above.
4. Run `npx open-assets render`.
5. Upload in Play Console (see [Upload to the stores](/guides/app-store-connect)).

## FAQ

<Accordions>
<Accordion title="What size are Google Play screenshots?">
Any size from 320px to 3840px per side with the long side at most twice the short side. 1080x1920 or 1080x2400 portrait is the common choice and meets the 1080px promotion minimum.
</Accordion>
<Accordion title="How many screenshots does Google Play allow?">
Up to 8 per device type, as of 2026-11-17.
</Accordion>
<Accordion title="Do I need tablet screenshots?">
Only if you want your listing to show on large screens; Google asks for at least 4 there. Add `tablet-7` and `tablet-10` export entries.
</Accordion>
<Accordion title="Can Google Play screenshots have transparency?">
No. Use 24-bit PNG without alpha or JPEG.
</Accordion>
<Accordion title="Does Open Assets make Android adaptive icons?">
No. It renders the 512px store icon only, not drawable or mipmap resources.
</Accordion>
</Accordions>
