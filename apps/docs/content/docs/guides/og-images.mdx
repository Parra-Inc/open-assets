The standard Open Graph (OG) image size is 1200x630 pixels, a 1.91:1 ratio, and X large cards look best at 1200x675. Open Assets renders both from one HTML template into your web app's `public/` folder.

Open Graph images are the previews that appear when someone shares your link in Slack, iMessage, LinkedIn or X. With Open Assets you design them in HTML and CSS, keep them in git next to your site, and render them as static files.

### Platform sizes and limits

| Platform | Recommended | Rules (as of 2026-11-17) |
| --- | --- | --- |
| Facebook | 1200x630 | At least 1200x630 for high resolution displays, 1.91:1, minimum 200x200, file under 8 MB (Meta sharing docs) |
| LinkedIn | 1200x627 or larger | Minimum 1200x627, 1.91:1, max 5 MB; under 401px wide shows as a thumbnail (LinkedIn help) |
| X (Twitter) | 1200x675 | See [X and Twitter card images](/guides/twitter-cards) |
| Slack, Discord, iMessage | 1200x630 | Read the same `og:image`; no separate size is needed |

## Command

```bash
npx open-assets add collection   # pick "OG Image / Social (1200x630, HTML)"
npx open-assets render --collection og
npx open-assets check            # in CI
```

The standard Open Graph image is 1200x630. X (Twitter) large summary cards use 1200x675. Both are close to 1.91:1 and 16:9, so one layout can serve both if the important content stays in the middle.

## One template per page

Each page that needs its own card gets its own template. A template's `name` drives its file name, and `{template}` in `outFile` lets one export entry write every page:

```json title="assets.json"
{
  "id": "og",
  "label": "Social Cards",
  "sourceSize": { "width": 1200, "height": 630 },
  "templates": [
    { "src": "assets/og/home.html", "name": "home", "label": "Home" },
    { "src": "assets/og/pricing.html", "name": "pricing", "label": "Pricing" },
    { "src": "assets/og/blog.html", "name": "blog", "label": "Blog" }
  ],
  "export": [
    { "name": "og", "label": "OG Image", "size": { "width": 1200, "height": 630 }, "outFile": "../web/public/og/{template}.png" },
    { "name": "twitter-card", "label": "X card", "size": { "width": 1200, "height": 675 }, "outFile": "../web/public/og/{template}-x.png" }
  ]
}
```

Run `npx open-assets render --collection og` and you get `public/og/home.png`, `public/og/home-x.png` and so on in the web app next door. `outFile` paths resolve from the project directory, so `..` reaches sibling folders in a monorepo. See [outFile](/guides/out-file).

<Callout type="info">
With a 1200x630 source, the 1200x675 render scales by 675 / 630 (about 1.07) to fill the height and crops about 86px from the right edge. If that cuts into your layout, use a second collection with a 1200x675 source for X, or leave a right margin in the template.
</Callout>

Templates are static files. Open Assets does not pass per-page data into a template (the only substitution it performs is [localized strings](/localization/strings)). For dozens of pages, generate the HTML files with a small script from your content, list them in `assets.json`, then render. For thousands of dynamic pages such as user profiles, render OG images at request time in your web framework instead.

## A card template

```html title="assets/og/pricing.html"
<!DOCTYPE html>
<html>
  <head>
    <meta charset="UTF-8" />
    <style>
      html, body { margin: 0; }
      .card {
        width: 1200px;
        height: 630px;
        box-sizing: border-box;
        padding: 80px;
        display: flex;
        flex-direction: column;
        justify-content: space-between;
        background: #0b1020;
        color: #fff;
        font-family: "Inter", "Helvetica Neue", Arial, sans-serif;
      }
      .eyebrow { font-size: 28px; opacity: 0.7; }
      h1 { font-size: 76px; line-height: 1.05; margin: 0; max-width: 900px; }
      .brand { display: flex; align-items: center; gap: 16px; font-size: 32px; }
      .brand img { width: 56px; height: 56px; border-radius: 12px; }
    </style>
  </head>
  <body>
    <div class="card">
      <div class="eyebrow">Pricing</div>
      <h1>Free for side projects. Fair for teams.</h1>
      <div class="brand">
        <img src="../../public/logo.png" />
        <span>myapp.com</span>
      </div>
    </div>
  </body>
</html>
```

Paint a background. PNGs keep transparency where nothing is painted, and social networks show transparent areas in unpredictable colors. To get smaller files, give `outFile` a `.jpg` extension and the size renders as JPEG.

## Wire it into your pages

A single site wide card can live at `public/og.jpg` (set `"outFile": "../web/public/og.jpg"`). Reference the files from your page metadata. In Next.js:

```ts title="app/pricing/page.tsx"
export const metadata = {
  openGraph: { images: ["/og/pricing.png"] },
  twitter: { card: "summary_large_image", images: ["/og/pricing-x.png"] },
};
```

## One template for the app icon, favicons and social cards

The [Xcode app icon](/guides/xcode-app-icon), the [favicons and PWA icons](/guides/favicons) and the [OG images](/guides/og-images) all live in the same `assets.json` and render with the same `npx open-assets render` command. One square icon template can feed both the `xcode` output and every favicon size, because a collection's `export` array accepts `xcode` entries and `outFile` sizes side by side:

```json title="assets.json (icon collection)"
"export": [
  { "type": "xcode", "path": "../MyApp/Assets.xcassets/AppIcon.appiconset" },
  { "name": "apple-touch-icon", "size": { "width": 180, "height": 180 }, "outFile": "public/apple-touch-icon.png" },
  { "name": "32", "size": { "width": 32, "height": 32 }, "outFile": "public/favicon-32.png" }
]
```

The 1200x630 OG card is a second collection in the same file, so when the templates share a stylesheet, one color change updates the icon, the favicons and the share card in one render.

## Steps

1. Run `npx open-assets add collection` and pick the OG Image preset, or paste the config above.
2. Design the card at 1200x630 with a painted background.
3. Point `outFile` at your web app's `public/` folder.
4. Run `npx open-assets render --collection og`.
5. Add the image to your page metadata and test the link in a share debugger.

## FAQ

<Accordions>
<Accordion title="What size should an OG image be?">
1200x630 pixels (1.91:1). Meta recommends at least that size and LinkedIn asks for a minimum of 1200x627.
</Accordion>
<Accordion title="What is the maximum OG image file size?">
As of 2026-11-17, Meta allows up to 8 MB and LinkedIn up to 5 MB. Rendering to `.jpg` usually keeps cards well under 300 KB.
</Accordion>
<Accordion title="Can Open Assets generate an OG image per page?">
Yes, one template per page with `{template}` in `outFile`. For thousands of dynamic pages, render at request time in your framework instead.
</Accordion>
<Accordion title="PNG or JPEG for OG images?">
Both work. A `.jpg` outFile renders JPEG, which is smaller and never transparent.
</Accordion>
<Accordion title="Does it write a favicon too?">
Yes, from a separate collection in the same `assets.json`. See [Favicons](/guides/favicons).
</Accordion>
</Accordions>
